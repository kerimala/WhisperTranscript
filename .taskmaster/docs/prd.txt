Overview

This product is a lightweight cross-platform desktop application (“WhisperDesk”) that empowers users to transcribe speech into text instantly. By leveraging OpenAI’s Whisper model, WhisperDesk eliminates the friction of manual transcription—whether the user records new audio or drops in existing files—and delivers clean, editable text that can be copied and pasted anywhere. It’s aimed at professionals, students, and anyone who needs a fast, reliable transcription tool on either Windows or macOS.

Core Features

1. Audio Capture & Input
	•	What it does: Allows users to record live voice or import existing audio files (MP3, WAV, M4A, etc.).
	•	Why it’s important: Covers both ad-hoc dictation and the transcription of pre-recorded material.
	•	How it works:
	1.	“Record” button launches system microphone;
	2.	“Upload” button opens file dialog for supported formats.

2. Automatic Transcription (Phase 1)
	•	What it does: Sends audio to the Whisper API for transcription and displays the result in the UI.
	•	Why it’s important: Offloads heavy ML processing to the cloud, enabling fast MVP development.
	•	How it works:
	1.	Audio is packaged and sent via HTTPS to the Whisper API;
	2.	API returns a JSON payload with timestamped segments;
	3.	Segments are concatenated into a single editable transcript.

3. Local Transcription Option (Phase 2)
	•	What it does: Enables users to download and run Whisper locally, leveraging GPU/CPU.
	•	Why it’s important: Provides offline capability, lower latency, and cost control.
	•	How it works:
	1.	Installer bundles or downloads Whisper weights;
	2.	Local inference engine (Python or C++ backend) runs on available hardware;
	3.	UI toggles between “Cloud” and “Local” modes.

4. System-wide Dictation Shortcut (Phase 3)
	•	What it does: Lets users invoke WhisperDesk from any text field via a global hotkey or context menu.
	•	Why it’s important: Creates seamless dictation across all applications (e.g., email, docs, chat).
	•	How it works:
	1.	Background daemon listens for a predefined hotkey (e.g., Ctrl+Shift+W);
	2.	On activation, a floating mini-window appears, records voice, transcribes in real time;
	3.	Final text is pasted into the active input field automatically.

User Experience

User Personas
	•	Journalist Jane: Needs quick transcriptions of interviews on-the-go.
	•	Developer Dave: Wants to dictate code comments or documentation without switching apps.
	•	Student Sarah: Transcribes lectures and study group sessions for note-taking.

Key User Flows
	1.	Quick Transcription: Launch app → Click “Record” → Speak → Transcript appears → Copy & paste.
	2.	Batch Transcription: Launch app → Click “Upload” → Select files → Wait for API/local processing → Export text.
	3.	System-wide Dictation: Press hotkey → Speak in mini-window → Wait → Text auto-inserts in active app.

UI/UX Considerations
	•	Default to Dark Mode for eye comfort and battery efficiency.
	•	Clean, minimal interface with two main buttons (Record/Upload) and a transcript pane.
	•	Status indicators for “Processing…”, “Error”, or “Completed.”
	•	Settings panel to switch between API vs. local mode, adjust language model size, and configure hotkey.

Technical Architecture

System Components
	•	Frontend (Electron): Cross-platform UI with React, managing user interactions.
	•	Backend:
	•	Phase 1: Node.js service wrapping Whisper API calls.
	•	Phase 2: Native host process (Python/C++) for local model inference.
	•	Phase 3: Background daemon for global hotkey capture and OS-level paste.

Data Models
	•	AudioRequest: { id, sourceType, filePath/blob, timestamp }
	•	TranscriptionResult: { id, segments: [{ start, end, text }], fullText }

APIs & Integrations
	•	Whisper Cloud API: Secure REST endpoints for upload and transcription.
	•	Local Whisper Runtime: Exposes a localhost gRPC or HTTP interface.
	•	OS Hooks (Phase 3): Uses Electron’s globalShortcut (Windows) and macOS Accessibility API.

Infrastructure Requirements
	•	Cloud: Standard HTTPS; no additional servers beyond a light proxy.
	•	Local: Python ≥3.8, PyTorch with CUDA (optional), disk space for model weights (~2 GB).
	•	Build Tooling: Electron Packager / Electron Builder for Windows (.exe) and macOS (.app).

Development Roadmap

Phase 1: Cloud-based MVP
	•	Implement Electron shell with Record/Upload UI.
	•	Integrate Whisper API client.
	•	Display and copy/paste transcript.

Phase 2: Local Inference Support
	•	Add model download manager and local inference service.
	•	Build switch in UI between cloud/local modes.
	•	Handle fallback if GPU unavailable (CPU mode).

Phase 3: System-wide Integration
	•	Develop background daemon for hotkey listening.
	•	Implement floating mini-window recording overlay.
	•	Automate pasting into active application field.

Logical Dependency Chain
	1.	Foundation: Electron app scaffold, basic UI, build pipeline.
	2.	MVP Transcription: Whisper API integration & transcript display.
	3.	Local Engine: Pack & launch local Whisper backend; UI toggle.
	4.	Hotkey Daemon: OS integration libraries & floating overlay.
	5.	End-to-End Flow: Combine recording → transcription → paste for global use.

Risks and Mitigations

Risk	Mitigation
Whisper API rate limits or downtime	Implement retry/back-off; offer API key configuration; clear error messaging.
Large model size & slow local inference on CPU	Provide GPU detection; warn about slower CPU mode; allow selection of smaller models.
Cross-platform OS hooks complexity (permissions, formats)	Prototype on each OS early; use established libraries (node-ffi, macOS Accessibility API).
User privacy concerns (audio data in cloud)	Clearly document privacy policy; default to local mode after install.
